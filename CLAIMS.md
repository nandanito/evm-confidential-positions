# CLAIMS register — EVM confidential positions (Paladin + Zeto)

**The register.** Every capability claim in a README, demo, post or conversation gets an entry
here with the test result or primary citation that supports it. **Before publishing anything,
diff the new claims against this register.** This is a human-gated checklist, not automation:
CI cannot judge whether prose overclaims.

Seeded 2026-09-26 from `docs/task-zero/TASK-ZERO-2026-09-26.md` and its `sources/`. Method and
row shapes copied from the reference project `xrpl-confidential-positions/CLAIMS.md`; content is
this project's own.

| Status | Meaning |
|---|---|
| `SUPPORTED` | evidence attached |
| `PENDING` | asserted, evidence not attached — **may not be published** |
| `BLOCKED` | never claim |
| `RETRACTED` | was claimed, found wrong — **keep the row** |

Grades: **A** two primary sources agree or executed · **B** one primary source · **C** stated inference · **GAP** not established.

## Standing prohibitions — never claim

| # | Claim | Why |
|---|---|---|
| P-1 | That a stock Paladin/Zeto devnet deployment is secure, trustless, non-custodial, production-ready or audited | It is none of these. The shipped Groth16 keys are Zeto's own **UNSAFE** test keys with δ=γ (E-5); the Paladin node holds all keys and all plaintext (E-8); no public audit exists (E-11) |
| P-2 | That the checked-in / shipped Zeto verifiers provide soundness for real value | They are generated with **no phase-2 contribution**; δ=γ in 30/30 (HEAD) and 32/32 (v0.2.2) verifiers, confirmed on our deployed bytecode. Zeto's README calls them UNSAFE; Zeto #186 is open. Forging with δ=γ is a known result (E-5) |
| P-3 | That a Zeto version or capability is present, without a dated command against the pinned commit | Paladin pins Zeto **v0.2.2**, 329 commits behind Zeto HEAD **v0.5.1**. A claim true at HEAD may be false at the pin, and vice versa (E-2, E-12) |
| P-4 | That Zeto hides *who* transacts on the base ledger | The **submitter EOA is public and `indexed`** on every transfer event (E-6, F-1). Only the Baby Jubjub owner identity inside commitments is hidden. Deposit/withdraw also expose the caller's EVM address (E-7) |
| P-5 | That a stock (deployed) Zeto token gives any third party — issuer, auditor, regulator — a decryption view | The 4 devnet variants (Anon, AnonEnc, AnonNullifier, AnonNullifierKyc) expose **no plaintext to any third party**. A designated decryptor exists **only** if you deploy the non-repudiation or qurrency variant (E-4). Paladin v1.0.0 cannot drive either. The non-repudiation view was executed on a standalone Zeto v0.2.2 deployment (E-19); at the pin, the qurrency circuit has no authority envelope (GAP-7) |
| P-6 | That Zeto's confidentiality hides transaction *shape*, timing, or frequency | Amounts and identities are hidden, but block timestamp, gas, and the **number of input/output notes (via zero padding)** are public; nullifier variants mask the UTXO graph, anon/anon_enc do **not** (E-6, F-1) |
| P-7 | That the non-repudiation auditor key is fixed at deploy time | It is set by `setArbiter` (`onlyOwner`) after deploy, rotatable **at any time with no event or timelock**, and a UUPS upgrade by the owner can change or remove it (E-4). **Executed** on our own deployment (E-20): 0 logs on `setArbiter`, effective in its own block, old envelopes stay with the old key. The rotation *transaction*, with the new key in its calldata, is public |
| P-8 | Any proof-size, gas or latency number without hardware, tool version, and method — **or a single fixed gas figure for a nullifier-variant transfer** | E-9/E-10 carry Apple M3 Pro + snarkjs 0.7.5 / Besu 25.8.0 QBFT gasPrice=0. Nullifier-transfer gas is data-dependent (1.38 M–2.31 M observed across thirteen transfers, E-10): quote the observed range and the mechanism, never one number. Do not quote a nullifier-variant *proving* time — it was not measured (GAP-2) |
| P-9 | That Zeto needs no trusted setup | It uses **Groth16, one ceremony per circuit** (E-5). This is the key contrast with XLS-96, which uses Bulletproofs (transparent, no ceremony) |
| P-10 | That a Paladin node is a neutral relay, or that node/operator compromise is survivable for its users | The node holds/derives all keys, generates proofs, and stores coin data + history as **plaintext** in Postgres; one mnemonic per node controls everything; devnet has no RPC auth. Compromise = read all + spend all for that node's tenants (E-8) |
| P-11 | **Any claim that a source does NOT say something, or that a capability is absent, without the search that would falsify it recorded alongside** | Carried from the reference project (its P-12). "No audit exists" is only ever "none found in corpus X on date Y" (E-11); "no revoke function" carries the grep (E-4 / `zeto-variants.md §4`) |
| P-12 | That analysis of Zeto/Paladin published work or of the ePrint Qurrency paper is original research | Cite the Zeto maintainers, the Qurrency authors (ePrint 2026/015), and issue #186's reporter where the work is theirs |
